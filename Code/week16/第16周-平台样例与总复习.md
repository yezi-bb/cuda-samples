# 第 16 周：平台样例与总复习

最后一周不引入新的通用 CUDA 机制。Tegra/cuDLA/NvSci 在台式 Windows 上以走读为完成标准。后三天用来把 15 周的笔记收成能讲出来的结构。

## 周一：Tegra 与 cuDLA（走读）

**路径**：`cpp/8_Platform_Specific/Tegra/README.md`，以及

- `cuDLAHybridMode`、`cuDLAStandaloneMode`
- `cuDLAErrorReporting`
- `cuDLALayerwiseStatsHybrid`、`cuDLALayerwiseStatsStandalone`

**做**

- 读分类 README：这些样例要 `-DBUILD_TEGRA=True`，交叉编译工具链在仓库 `cmake/toolchains/`
- 用一张表对比 hybrid 与 standalone：DLA 是否由 CUDA 编程、统计信息从哪条 API 出来、错误如何报回 CUDA
- 不要在本机强行配置 DriveOS 或 QNX，除非你已经有目标文件系统。README 的 QNX 与 QNX Safety 小节只要求你能指出：`TARGET_FS` 是给谁用的（`cudaNvSci` 需要板端的 NvSci 头文件和库）

**想清楚**

1. cuDLA 样例教的是加速器互操作，不是又一种矩阵乘写法。
2. Safety 工具链多了 `-safety-compat`，样例集合收成 `matrixMul` 和 `cudaNvSci`。这说明「全仓库」和「安全编译配置」不是同一个构建。
3. 交叉编译产物要在设备上跑。主机编过不等于你验证过。

**完成标准**：hybrid / standalone 对照表，外加一句「本机未运行，原因是没有 Tegra 目标机」。

## 周二：NvSci、NvMedia、EGL（走读）

**路径**

- `cpp/4_CUDA_Libraries/cudaNvSci`
- `Tegra/cudaNvSciBufMultiplanar`
- `Tegra/cudaNvSciNvMedia`
- `Tegra/EGLSync_CUDAEvent_Interop`
- `Tegra/simpleGLES`、`simpleGLES_EGLOutput`、`fluidsGLES`、`nbody_opengles`

**做**

- `cudaNvSci`：两个 CPU 线程分别导入 NvSciBuf/NvSciSync，做旋转和 RGBA 转灰度。把同步对象和缓冲对象分开记
- 多平面样例：YUV420 的平面如何进 CUDA surface
- EGL 与 GLES 样例：对照第 12 周桌面 OpenGL，差在 EGLStream/EGLSync/EGLOutput，而不是差在物理公式
- `nbody_opengles` 与 `fluidsGLES` 标明「算法已在第 12 周读过，这里只换显示后端」

**想清楚**

1. NvSciBuf 解决分配和跨引擎共享，NvSciSync 解决开始和结束的顺序。
2. EGLSync 对 CUDA event 的价值是 GPU 侧等待，不把 CPU 堵在中间。这和第 12 周 Vulkan 信号量是同一类设计。
3. 图形后端可以换，kernel 里的粒子或流体更新不应因此改数学。

**完成标准**：每个 Tegra 子目录一行笔记：主题、对应的桌面样例、本机状态（未构建）。
