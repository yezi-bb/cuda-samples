# 第 12 周：仿真与图形互操作

`cpp/5_Domain_Specific/` 后半，外加概念册里没读透的粒子。窗口系统样例以走读数据通路为主，能弹出窗口再看效果。

## 周一：n-body（精读）

**路径**：`nbody`

**做**

- 读 README：全对引力、tile 到共享内存、多 GPU 时用零拷贝读系统内存。命令行 `-numbodies=`、`-numdevices=`
- 精读单 GPU kernel：一个线程更新一个天体，tile 加载其他天体位置
- 多 GPU 路径对照第 4 周零拷贝和第 3 周 `simpleZeroCopy`。没有多块 GPU 就只读这段，不要假造加速比

**想清楚**

1. 计算量相对天体数是平方。共享内存 tile 减少的是全局加载次数，不是算法复杂度。
2. 多 GPU 切分的是天体子集还是力的部分和？
3. 和 `particles`（第 7 周，均匀网格）相比，n-body 为什么不能用同样的网格截断邻居？

**完成标准**：能解释 tile 大小和共享内存容量的关系。

## 周二：流体、烟雾、行军立方体、Mandelbrot

**路径**：`fluidsGL`、`smokeParticles`、`marchingCubes`、`Mandelbrot`、`FDTD3d`

**做**

- `fluidsGL`：稳定流体里的 cuFFT 投影。`test_args.json` 通常 skip 图形样例，你本地可以手动跑，自动化测试不要指望它
- `marchingCubes`：用 Thrust 扫描做流压缩，只留下相交的体素。这是第 5 周 scan 的直接应用，优先看这一段
- `FDTD3d`：三维模板。看 halo 和共享内存，对照第 6 周卷积
- `smokeParticles`、`Mandelbrot`：无显示则走读。Mandelbrot 记下双精度或 double-single 的精度路径在哪条分支

**想清楚**

1. 行军立方体如果没有扫描压缩，输出三角形会有多少空洞槽位？
2. FDTD 的模板半径和卷积 halo 是不是同一类边界问题？
3. 流体样例里 cuFFT 解决的是哪个方程步骤，不是「把图变模糊」。

**完成标准**：点名一个样例说明「扫描用于压缩」，点名另一个说明「FFT 用于求解」。

## 周三：OpenGL 互操作（有显示则运行 simpleGL）

**路径**：`simpleGL`、`postProcessGL`。分类 README 还提到 `simpleGLES_screen`；若当前树里没有这个目录，就改读 `cpp/8_Platform_Specific/Tegra/simpleGLES` 的 README，只对比显示后端。

**做**

- `simpleGL`：CUDA 改顶点，OpenGL 画出来。圈出注册缓冲、映射、kernel、解映射、绘制
- `postProcessGL`：OpenGL 先渲染，CUDA 再后处理。和 simpleGL 比，谁先拥有图像
- GLES/screen 版本多在嵌入式或 QNX。Windows 桌面走读差异：显示系统从 GLX/WGL 换成 Screen

**想清楚**

1. 映射期间，图形 API 能不能同时画这块缓冲？
2. 同步点在解映射，还是在 CUDA 流和 GL 命令队列之间还有别的对象？
3. 这些样例被 `run_tests.py` skip 的原因是自动化环境没有显示器，不是算法不能测。

**完成标准**：写出注册 → 映射 → 计算 → 解映射 → 绘制的顺序。

## 周四：Direct3D（Windows 上优先这天真正编译）

**路径**：`simpleD3D11`、`simpleD3D11Texture`、`simpleD3D12`

**做**

- 这是本仓库里少数「Windows 比 Linux 更合适」的样例。按各目录 README 看需要的 Windows SDK
- `simpleD3D11`：CUDA 更新 D3D11 缓冲，用 keyed mutex 同步
- `simpleD3D11Texture`：2D、3D、立方体纹理由 CUDA 写入再交给 D3D 画
- `simpleD3D12`：顶点缓冲里的正弦波，用 D3D12 fence 和 CUDA 同步

**想清楚**

1. keyed mutex 和 fence 都是跨 API 同步，分别出现在哪一版 D3D？
2. CUDA 写入的是顶点缓冲还是纹理，两种样例各是哪一种？
3. 和第 4 周纯 CUDA 纹理相比，多出来的不可跳过步骤是外部资源导入。

**完成标准**：至少一份 D3D 样例要么跑起来，要么把 CMake 报错原文记下来（缺 SDK 也算完成走读）。

## 周五：Vulkan 三件套（有 SDK 则精读 simpleVulkan）

**路径**：`simpleVulkan`、`simpleVulkanMMAP`、`vulkanImageCUDA`

**做**

- 三份都依赖 Vulkan SDK 和 GLFW。README 指向各目录的构建说明
- `simpleVulkan`：CUDA 导入 Vulkan 顶点缓冲，用信号量同步
- `simpleVulkanMMAP`：方向反过来，CUDA 用 `cuMemMap` 导出，Vulkan 导入
- `vulkanImageCUDA`：导入的是图像，做盒式滤波，不是顶点正弦波

**想清楚**

1. 信号量导入解决的是 GPU 上的队列等待，避免 CPU 来回 `cudaDeviceSynchronize`。
2. 缓冲互操作和图像互操作，CUDA 侧一个变成设备指针，一个变成数组或表面。
3. 领域册到此结束。把「无窗口就能跑」和「必须有图形栈」分成两列，检查第 11 周有没有误标。

**完成标准**：Vulkan 三份各一句：谁分配、谁导入、同步对象是什么。编不过不算失败，把缺的依赖写清楚。
