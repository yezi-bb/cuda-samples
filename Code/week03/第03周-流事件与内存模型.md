仍在 `cpp/0_Introduction/`。本周回答：CPU 和 GPU 怎样重叠，主机内存有哪几种，统一内存在样例里怎么用。

**路径**：`asyncAPI`

**做**

- 构建运行。把 `cudaEventRecord`、`cudaEventQuery`、`cudaEventSynchronize` 在时间线上标出来
- 找到 CPU 在 GPU 干活时做的那部分工作，确认它不是靠忙等事件

**想清楚**

3. 用事件量到的时间，量的是哪一段 GPU 工作？

**完成标准**：能画出一条「入队 → CPU 并行干活 → 查询事件 → 同步」的时序。

## 周二：用流重叠拷贝和计算（精读 simpleStreams，对照 simpleMultiCopy）

**路径**：`simpleStreams`、`simpleMultiCopy`

**做**

- 精读 `simpleStreams`：分段 HtoD、kernel、DtoH 如何排进多条流
- 对照 `simpleMultiCopy`：计算能力 2.0 以上的双向拷贝引擎在样例里如何体现
- 两份都看锁页内存（pinned）是用哪一个 API 分配的

**想清楚**

1. 为什么可分页内存上的 `cudaMemcpyAsync` 经常退化为同步？
2. 流的数量和分段大小谁对重叠更敏感？
3. 正确性校验放在哪一次同步之后？

**完成标准**：能解释「没有锁页内存就没有真正的重叠」。

## 周三：回调、零拷贝、统一内存（精读两个，对照一个）

**路径**：`simpleCallback`、`simpleZeroCopy`、`UnifiedMemoryStreams`

**做**

- `simpleCallback`：流回调在哪个线程执行，回调里为什么不能再做会阻塞该流的 CUDA 调用
- `simpleZeroCopy`：`cudaHostAlloc` + `cudaHostGetDevicePointer`，kernel 直接读写主机锁页内存
- `UnifiedMemoryStreams`：`cudaMallocManaged` 与 OpenMP 线程如何分到同一块 GPU 上的工作。没有 OpenMP 就走读

**想清楚**

1. 零拷贝省掉了哪一次拷贝，代价是每次访问都走总线吗？
2. 统一内存的缺页迁移和零拷贝的映射是不是同一机制？
3. 回调适合做同步点上的主机逻辑，还是适合做大数据搬运？

**完成标准**：一张表，三行分别写分配 API、谁发起访问、数据是否显式拷贝。

## 周四：半精度、L2 策略、原子的前奏（对照为主）

**路径**：`fp16ScalarProduct`、`simpleAttributes`

**做**

- `fp16ScalarProduct`：看 FP16 向量点积如何在设备上累加，主机如何做误差比较
- `simpleAttributes`：流的 L2 访问策略窗口（access policy window）。计算能力低于 8.0 时走读，README 写明性能差异只有 8.0+ 才看得出来

**想清楚**

1. FP16 的符号、指数、尾数各占多少位（README 的 CUDA Features 一节有定义）？
2. L2 策略窗口控制的是容量分区还是替换优先级？
3. 这两个样例为什么放在 Introduction 而不是 Performance？

**完成标准**：能指出「功能正确」和「策略影响性能」在这两个样例里分别靠什么验证。
