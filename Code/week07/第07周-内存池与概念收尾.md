# 第 7 周：内存池与概念册收尾

本周清完 `cpp/2_Concepts_and_Techniques/` 剩余样例。流序分配是重点，图像和 EGL 样例按依赖走读。

## 周一：流序内存分配（精读）

**路径**：`streamOrderedAllocation`

**做**

- 构建运行。对照 `cudaMalloc`/`cudaFree` 与 `cudaMallocAsync`/`cudaFreeAsync`
- 看 `cudaMemPool` 如何挂到流上，释放何时对后续同一条流可见
- 找出样例在什么地方仍然需要显式同步

**想清楚**

1. 异步分配解决的是「分配本身进流、避免全局同步」，不是把带宽变高。
2. 池和每次 `cudaMalloc` 的区别在复用，还是在地址空间？
3. 在默认流里调用 `cudaFreeAsync`，和指定流有什么不同？

**完成标准**：能画出「分配入队 → kernel 入队 → 释放入队」且中间没有 `cudaDeviceSynchronize` 的序列。

## 周二：池的 IPC 与 P2P（对照，多半走读）

**路径**：`streamOrderedAllocationIPC`、`streamOrderedAllocationP2P`

**做**

- IPC 版：池的导出句柄如何交给另一进程。对照第 4 周 `simpleIPC`
- P2P 版：对端 GPU 如何访问本端流序分配。对照 `simpleP2P`
- 单 GPU、非 TCC Windows：走读即可，写明缺的运行条件

**想清楚**

1. 共享的是池，还是池里的一次分配？
2. 对端访问之前要不要 peer access？
3. 这两份样例的算法内容为什么几乎为空，重点全在生命周期？

**完成标准**：三份流序样例各用一句话：单设备池、跨进程池、跨 GPU 池。

## 周三：Thrust 分割树、区间运算、上下文迁移

**路径**：`segmentationTreeThrust`、`interval`、`threadMigration`

**做**

- `segmentationTreeThrust`：Borůvka 最小生成树做图像分割。抓 Thrust 用在哪一步，不深挖图论
- `interval`：区间算术的 C++ 模板和递归。README 写递归模式要 SM 2.0+。看设备端递归如何写，而不是把 Boost 配置头读完（`interval/boost/` 是移植来的配置，跳过）
- `threadMigration`：CUDA 上下文可以建好再绑到另一条主机线程。对照第 4 周多线程样例

**想清楚**

1. 上下文迁移改变的是「哪个 CPU 线程能发命令」，不是 kernel 里的线程块。
2. 设备递归和动态并行（第 8 周）有什么关系，这份样例有没有从设备启动新 kernel？
3. 分割树样例的正确性最终拿什么和 CPU 比？

**完成标准**：能把「主机线程 / CUDA 上下文 / 设备线程块」三个词放进同一段话且不混用。

## 周四：图像类概念样例（能编几份编几份）

**路径**：`boxFilter`、`dct8x8`、`imageDenoising`、`particles`

**做**

- `boxFilter`：盒式滤波 + OpenGL 显示。无显示则走读滤波 kernel
- `dct8x8`：8×8 DCT 的朴素实现和更传统的分解实现，两套都点出函数名
- `imageDenoising`：KNN 与 NLM。NLM 使用共享内存的那条路径做精读
- `particles`：均匀网格，原子或 Thrust 基数排序建网格。命令行 `-particles=` 控制规模。无 OpenGL 时走读模拟部分，跳过渲染

**想清楚**

1. DCT 样例为什么说比片元着色器更容易改数据复用？
2. 粒子网格用原子和用排序，输出的是同一种「格子 → 粒子」结构吗？
3. 这些样例和周一的内存池没有算法关系。它们留在概念册是因为展示问题分解，不是因为新 API。

**完成标准**：四份里至少一份写出 kernel 输入图像（或粒子数组）的布局。
