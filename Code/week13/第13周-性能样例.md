# 第 13 周：性能样例

`cpp/6_Performance/` 只有五份，但每一份都要用前面几周的机制来解释数字。本周允许反复跑、改问题规模，不要求改算法。

分类 README 没列 `LargeKernelParameter`，目录里有，周四一起读。

## 周一：对齐（精读）

**路径**：`alignedTypes`

**做**

- 构建运行。记录对齐结构和错位结构的每元素拷贝吞吐
- 看结构体如何被故意偏移，以及向量化加载（如 `float4`）在什么时候失效
- 把差异倍数写进笔记，并注明 GPU 型号，避免以后把别人的数字当成自己的

**想清楚**

1. 错位慢，主要是扇区浪费还是指令拆分？样例输出能区分到哪一层？
2. 第 2 周 `vectorAdd` 若把 `float` 换成带填充的结构，会踩中同一问题吗？
3. 对齐是正确性问题还是性能问题？这份样例的校验在比什么？

**完成标准**：能用本机数字说明「同一份数据量，布局不同则带宽不同」。

## 周二：转置（精读）

**路径**：`transpose`

**做**

- 样例会跑多种转置：朴素、共享内存 tile、padding 避免 bank conflict、可能还有对角化 tile 以改善分区冲突
- 每种跑完把带宽记下来，在源码里找到对应 kernel 名
- 画一个 32×32 tile：无 padding 时，一列线程如何打在同一个共享内存 bank 上

**想清楚**

1. 转置的算术强度极低，所以它是带宽样例，不是计算样例。
2. 共享内存 bank 冲突和全局内存的分区/扇区冲突是两套硬件。样例哪些版本在治哪一套？
3. 和第 2 周矩阵乘的 tile 相比，转置 tile 没有复用，只有改变方向。

**完成标准**：能指出你本机最快的那个 kernel 名字，以及它多做了哪一步（padding 或对角块）。

## 周三：统一内存性能（精读）

**路径**：`UnifiedMemoryPerf`

**做**

- README：同一矩阵乘，比较统一内存（有无 hints）、零拷贝、可分页、锁页、同步拷贝和异步拷贝
- 跑默认规模。把每一种模式的一行结果抄下
- 在源码里找到 `cudaMemAdvise` 或 `cudaMemPrefetchAsync` 出现的模式，对照第 10 周多 GPU 共轭梯度里的预取

**想清楚**

1. 哪一种模式最接近第 3 周 `simpleZeroCopy`，哪一种最接近显式 `cudaMemcpy`？
2. 不加 hint 的统一内存为什么可能接近「先缺页再迁移」的最差情况？
3. 这份样例的结论是否依赖你只有一块 GPU？笔记里写上设备数量。

**完成标准**：一张模式对照表，行是内存种类，列是「谁触发传输」和「本机耗时」。

## 周四：图的伸缩与大参数（精读 cudaGraphsPerfScaling）

**路径**：`cudaGraphsPerfScaling`、`LargeKernelParameter`

**做**

- 图样例：图变大时，实例化和启动的主机耗时怎么变。对照第 8 周「空图不值得捕获」的判断，用数字验证
- `LargeKernelParameter`：CUDA 12.1 放宽 kernel 参数大小。看样例如何构造大参数、如何与 `cudaMemcpyToSymbol` 那条旧路径比较
- 两份都运行。关注主机时间还是设备时间，在笔记里分开写

**想清楚**

1. 图的收益主要在启动开销被摊薄，不在设备算术变快。
2. 参数很大时，旧做法是放进常量内存或全局缓冲。新做法把更多数据留在启动参数里。正确性一样时比的是方便程度和拷贝次数。
3. 如果图里只有一个大 kernel，捕获还值不值得？用今天的曲线回答，不要用口号。

**完成标准**：能根据你自己的输出说「图节点数增加到多少以后，启动耗时不再线性吓人」或如实写「在本机规模内仍近似线性」。
