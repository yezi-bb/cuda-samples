# 第 11 周：领域样例，图像与金融

`cpp/5_Domain_Specific/` 前半。本周选不依赖窗口系统、或窗口失败时仍能读 kernel 的样例。图形互操作留到第 12 周。

## 周一：边缘与视差（精读 Sobel）

**路径**：`SobelFilter`、`stereoDisparity`

**做**

- `SobelFilter`：8 位灰度的梯度。对照第 6 周 `FunctionPointers` 里的 Sobel，这次重点是滤波本身和共享内存
- `stereoDisparity`：SIMD SAD 内建函数算视差。计算能力要求见 README（2.0+）
- 输入图像从哪读（文件、生成、FreeImage）写进笔记。缺图像库就走读

**想清楚**

1. Sobel 的水平核和垂直核能否像可分离卷积一样拆开？
2. SAD 为什么适合用 SIMD 内建，而不是每字节一次减法？
3. 这两个样例的输出是图像。校验是和参考图比，还是和 CPU 实现比？

**完成标准**：能写出 Sobel 一个像素对其邻域的依赖范围。

## 周二：平滑、双边、双三次（精读 recursiveGaussian）

**路径**：`recursiveGaussian`、`bilateralFilter`、`bicubicTexture`

**做**

- 精读 `recursiveGaussian`：Deriche 递归高斯，耗时不随滤波宽度增长。命令行 `-sigma=` 在 `test_args.json` 里有多组，看 README 或 JSON 即可
- `bilateralFilter`：权重同时看空间距离和颜色距离，所以边缘能留下。无 OpenGL 则只读权重 kernel
- `bicubicTexture`：用纹理做双三次 B 样条。对照第 4 周的线性纹理滤波，多出来的是软件算权重还是硬件采样

**想清楚**

1. 递归滤波的「与 σ 无关」是近似还是精确，样例用什么证明它仍然像高斯？
2. 双边滤波为什么不能简单拆成行列两次一维滤波？
3. 双三次相对双线性，采样次数大概多几倍？

**完成标准**：三种平滑各一句：递归高斯看半径无关，双边看保边，双三次看插值阶数。

## 周三：变换类（精读 convolutionFFT2D）

**路径**：`convolutionFFT2D`、`dwtHaar1D`、`fastWalshTransform`、`dct8x8`（概念册那份如果第 7 周没读完，今天补）

**做**

- `convolutionFFT2D`：大核卷积走 FFT。把填充、前向变换、频域相乘、逆向变换四步标出。这是第 10 周海洋 FFT 的算法版
- `dwtHaar1D`：长度必须是 2 的幂的一维 Haar 小波。看原地分解的层级
- `fastWalshTransform`：同样要求 2 的幂。看蝶形如何映射到线程

**想清楚**

1. 什么核尺寸下空域卷积会输给 FFT 卷积（样例 README 的主张是「很大的核」）？
2. Haar 与 Walsh 都有原地蝶形。它们和上周归约的树形有什么像？
3. 变换类样例很少用共享内存技巧当主角。本周不要强行套第 5 周的模板。

**完成标准**：FFT 卷积的四步能按顺序默写，并知道哪一步是 cuFFT。

## 周四：体数据与视频预处理

**路径**：`volumeRender`、`volumeFiltering`、`dxtc`、`NV12toBGRandResize`

**做**

- `volumeRender`：三维纹理光线行进。无显示则走读采样循环
- `volumeFiltering`：三维纹理读、三维表面写。把第 4 周表面写入扩展到 3D
- `dxtc`：DXT 压缩。看块压缩如何让每个线程处理一个固定大小的块
- `NV12toBGRandResize`：README 的两条路径（先转 BGR 再缩放，或先缩放再转）。这是和推理前处理最接近的一份，优先精读数据布局（NV12 的 Y 平面和交错 UV）

**想清楚**

1. NV12 为什么不是紧密的 RGB，硬件解码器为什么爱用它？
2. 体渲染的线程是一条光线还是一个像素？
3. DXT 的输出比输入小，带宽节省发生在压缩之后的使用阶段，不是压缩 kernel 本身。

**完成标准**：能画出 NV12 两平面在内存里的大致排列。

## 周五：金融四件套（精读 BlackScholes）

**路径**：`BlackScholes`、`binomialOptions`、`quasirandomGenerator`、`SobolQRNG`

**做**

- `BlackScholes`：一批欧式期权的看涨/看跌。一个线程一份合约。看主机如何生成参数、如何比误差
- `binomialOptions`：二叉树定价。看共享内存里如何沿树回推
- 两个随机数样例：Niederreiter 与 Sobol。对照第 6 周 cuRAND 的拟随机，这次是样例自己实现生成器

**想清楚**

1. Black-Scholes 这份负载为什么几乎是纯算术、很少通信？
2. 二叉树样例的并行度在「很多期权」还是「一棵树的一层」？
3. 自写 QRNG 和 cuRAND 的 QRNG 同时存在于仓库里，学习时你应把谁当 API 参考、谁当算法参考？

**完成标准**：金融样例笔记里写明「并行维度是期权数量」。周六把本周和「库做变换 / 手写滤波」的分界再写三句。
