# 第 5 周：设备查询与并行原语

Utilities 只有三个样例，周一做完。周二起进入 `cpp/2_Concepts_and_Techniques/` 里最值得精读的算法：归约、扫描、直方图。

## 周一：把设备问清楚（精读）

**路径**：`cpp/1_Utilities/deviceQuery`、`deviceQueryDrv`、`topologyQuery`

**做**

- 再跑一次 `deviceQuery`，把输出按组摘进笔记：计算能力、SM 数量、每块共享内存、Warp 大小、并发拷贝、统一寻址、合作启动（cooperative launch）
- `deviceQueryDrv` 只对照：同一属性用 `cuDeviceGetAttribute` 而不是 `cudaGetDeviceProperties`
- `topologyQuery`：多 GPU 时的 PCI 距离和 CPU 亲和。单 GPU 也运行，看它如何退化

**想清楚**

1. Warp 大小在这份输出里是多少，后面所有「32 线程」假设从哪来？
2. 哪些属性决定第 8 周的多块协作组能不能跑？
3. README 为什么把 `bandwidthTest` 删掉，并指向外部的 nvbandwidth？

**完成标准**：笔记里有一份「本机限制今后哪些样例」的清单，和第一周的能力表对齐。

## 周二：reduction（精读，本周最重要的一天）

**路径**：`cpp/2_Concepts_and_Techniques/reduction`

**做**

- 构建运行。样例会依次跑多种归约实现并打印带宽或耗时，把每一种的名字抄下来
- 顺着源码看进化顺序，至少分清这几步：交错寻址、连续寻址、展开最后一个 warp、`__shfl_down_sync`、`__reduce_add_sync`、cooperative groups 的 `reduce`
- 不要在一天内背下每个变体的全部代码。画出「树形相加时，哪些线程在第 k 步还活着」

**想清楚**

1. 为什么全局内存上做完全归约会让带宽很差？
2. 共享内存归约之后，一个 block 只剩一个部分和，块与块之间怎么合并？
3. Shuffle 相对共享内存，省掉了哪一次同步？

**完成标准**：能口头讲出至少四种实现的差异，并知道最终结果如何和 CPU 对照。

## 周三：单次归约的另外两条路（对照）

**路径**：`reductionMultiBlockCG`、`threadFenceReduction`、`scalarProd`

**做**

- `reductionMultiBlockCG`：多块协作组把昨天的「再启动一个 kernel 合并」收成一次启动。需要计算能力 6.0+ 且支持计算抢占，否则走读
- `threadFenceReduction`：用全局原子和 `__threadfence` 做单 kernel 归约，对比昨天的两段式
- `scalarProd`：点积是「逐元素乘再归约」。看它复用了归约的哪一部分

**想清楚**

1. 协作启动（`cudaLaunchCooperativeKernel`）为什么对占用和网格大小有限制？
2. `threadfence` 保证的是可见性，不是互斥。样例里谁负责互斥？
3. 点积的数值误差和整数求和的误差是不是同一类问题？

**完成标准**：一张表，三行：跨块同步手段、需要的硬件、kernel 启动次数。

## 周四：scan 与 warp 内扫描（精读 scan）

**路径**：`scan`、`shfl_scan`

**做**

- 精读 `scan`：前缀和的定义（每个输出是其左侧所有输入之和），分清 block 内扫描和 block 间扫描的第二次 kernel
- 对照 `shfl_scan`：`__shfl_up_sync` 如何在一个 warp 里做扫描，再如何扩展到整个 block
- 用长度为 8 的手写例子核对 inclusive/exclusive 的差别（以样例实现为准，不要凭记忆改定义）

**想清楚**

1. 扫描的工作量相对输入长度是线性还是 `n log n`，样例关心的是哪一个？
2. 为什么扫描是后面 stream compaction、基数排序的地基？
3. Shuffle 扫描的参与线程必须满足什么对齐？

**完成标准**：给定小数组，能写出样例所定义的扫描结果，并指出哪一次 kernel 处理块间进位。

## 周五：histogram（精读）

**路径**：`histogram`

**做**

- 看 64-bin 和 256-bin 两套实现
- 重点：每块先在共享内存里累加，再原子加到全局直方图。找冲突减轻的手法（例如每线程多份私有 bin，或 padding 避免 bank conflict）
- 运行并确认与 CPU 直方图一致

**想清楚**

1. 如果所有线程直接 `atomicAdd` 到全局 bin，瓶颈在哪里？
2. 256-bin 为什么比 64-bin 更吃共享内存？
3. 直方图和归约的相同点是「结合律」，不同点是输出槽位数。

**完成标准**：能说明共享内存直方图如何减少全局原子次数。周六复盘三种原语：归约、扫描、直方图，各用一个样例名字记住。
